# 🖥 السيرفرات / المزودون المتعددون — بنية ديناميكية

هذا ملف يشرح الفكرة اللي طلبها صاحب البوت، وكيف تتحقق، وكيف تتمدد على باقي
الأقسام (الرشق، الألعاب، الأرقام...).

---

## 1) المطلوب (بساطة)

> «أضيف 5 مزودين لنفس القسم، والمستخدم قبل ما يختار الدولة يختار السيرفر،
> وكل سيرفر مربوط بمزود لحاله، وأتحكم فيه بالكامل من لوحة الأدمن.»

## 2) البنية المختارة

كل خدمة أرقام `NumberService` يمكن أن تحوي جدول سيرفرات `NumberServer`:

| الحقل | المعنى |
|---|---|
| `number_service_id` | الخدمة (واتساب، تيليجرام...) التي ينتمي لها السيرفر |
| `provider` | المزود المرتبط (5sim / HeroSMS / SMS-Activate / SMSHub) |
| `name_ar` / `emoji` | الاسم والرمز الظاهر للمستخدم |
| `is_active` | تفعيل/تعطيل السيرفر |
| `sort_order` | ترتيب ظهور السيرفرات |

السبب في تصميم السيرفر كجدول مستقل (وليس حقول في الخدمة): لأنه **قابل للتوسّع
بدون تعديل كود** — تضيف سيرفر جديد = صف جديد في قاعدة البيانات، وما تكتب كود.

## 3) ماذا نفّذنا (المرحلة الأولى: قسم الأرقام)

- ✅ جدول `number_servers` + هجرة Alembic جديدة (`f1e2d3c4b5a6`).
- ✅ خدمة `services/number_server_service.py`:
  - إضافة سيرفر
  - تعطيل/تفعيل
  - تعديل الاسم/الإيموجي/المزود
  - حذف
  - إنشاء تلقائي «سيرفر لكل مزود عليه كود» من أزرار الخدمة
- ✅ تدفق المستخدم أصبح:
  ```
  زر الأرقام ← اختر الخدمة
              ← اختر السيرفر (5sim / HeroSMS / SMS-Activate ...)
              ← اختر الدولة
              ← السعر (من المزود المختار فقط)
              ← شراء
  ```
- ✅ الشراء الفردي والجملة مربوطان بـ `strict_provider`:
  - بدون سيرفر → نفس السلوك القديم (أرخص مزود + Failover).
  - مع سيرفر → يشتري من المزود المختار فقط ولا ينتقل لغيره (شفافية السيرفر).
- ✅ لوحة الأدمن: `إدارة خدمات الأرقام` ← أي خدمة ← «⚙️ السيرفرات/المزودين التابعين».

## 4) التوسع على كل الأقسام (الرشق / الألعاب / المتجر) — منفّذ

نفس النمط أصبح جدولاً عمومياً `store_servers`:

| الحقل | المعنى |
|---|---|
| `scope` | `category` / `subcategory` / `global` |
| `scope_id` | رقم القسم (أو 0 لم يعمل على كل الأقسام) |
| `provider_kind` | `api` (متجر/رشق/ألعاب) أو `number` (أرقام) |
| `api_provider_id` | المزود المرتبط إذا كان API |
| `provider_value` | المزود المرتبط إذا كان أرقاماً |
| `margin_percent` | نسبة ربح السيرفر (تُطبق عند الشراء) |
| `name_ar` / `emoji` / `description` | العرض للمستخدم |
| `is_active` / `sort_order` | تفعيل وترتيب |

وسيرفر الأرقام `NumberServer` أصبح يحمل `margin_percent` أيضاً: من لوحة
أدمن الأرقام ← أي خدمة ← «⚙️ السيرفرات/المزودين التابعين» ← أي سيرفر ←
«💰 نسبة الربح». تُطبَّق على الشراء الفردي والجملة وتتفوق على هامش
الخدمة/الدولة الحالي.

### هامش «كل تطبيق/قسم فرعي» (التحكم الدقيق بالأسعار)

من «إدارة الأقسام» يمكن ضبط هامش مستقل على:
- القسم الرئيسي (مثل «الرشق»).
- أي قسم فرعي/تطبيق (مثل «انستقرام»).
- أي خدمة داخل التطبيق (مثل «لايكات» أو «متابعون»).

أولوية الهامش الفعّال عند العرض والشراء:

```
منتج (يدوي) > قسم فرعي/خدمة > تطبيق > قسم رئيسي > سيرفر > السعر المحفوظ
```

- أي منتج سحوب تلقائياً يحمل هامشاً ضمنياً؛ هذا الهامش ليس «يدوياً»،
  لذلك هامش تطبيقه/قسمه يتحكم به ويعيد حساب سعره فوراً.
- إذا ضبط الأدمن هامش المنتج نفسه من شاشة المنتج، يُعتبر يدوياً ولا
  يُلمس عند تغيير هامش القسم.
- هامش السيرفر يُستخدم فقط عندما لا يوجد هامش تطبيق/قسم/منتج مضبوط.

المسار المتصل حالياً:
- المتجر الذكي (`store:section:`) → إن وُجد سيرفر «عام» يُعرض اختيار
  السيرفر أولاً، ثم منتجات مزوده فقط.
- الأقسام الديناميكية (`cat:` → `subcat:`) → إن وُجد سيرفر للقسم الفرعي
  (أو للأب / العام) يُعرض الاختيار قبل المنتجات.
- الشراء: `_execute_purchase` يقرأ `server_id` من الجلسة ويطبّق
  `margin_percent` على سعر التكلفة (يحلّ الهامش القديم) ثم يحسب الإجمالي.
- الأرقام: لا تزال تستخدم `NumberServer` بنظامها الحالي.

## 5) لوحة الأدمن

`/admin` ← «🛍 المتجر والخدمات والرشق» ← «🖥 السيرفرات العامة»:
- عرض كل السيرفرات.
- إضافة سيرفر: اختيار النطاق (قسم رئيسي/فرعي/عام) → الاسم → الإيموجي →
  نوع المزود → المزود → نسبة الربح.
- إدارة: تفعيل/تعطيل، تعديل الاسم/الإيموجي/الوصف/نسبة الربح، حذف.

## 6) كيف تشغّله؟

1. حدّث البوت بالكود الجديد (فيه هجرة قاعدة بيانات).
2. افتح: `/admin` ← «🛍 المتجر والخدمات والرشق» ← «🖥 السيرفرات العامة».
3. أضف سيرفراً واربطه بمزود واضبط نسبة ربحه.
4. إذا ربطته بقسم فرعي يظهر للمستخدم قبل منتجات ذلك القسم؛
   وإذا جعلته «عام» يظهر في المتجر الذكي (ألعاب/رشق/تطبيقات)
   وفي كل قسم لا يحمل سيرفراً خاصاً به.

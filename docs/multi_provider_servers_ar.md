# 🖥 السيرفرات / المزودون المتعددون — بنية ديناميكية

هذا ملف يشرح الفكرة اللي طلبها صاحب البوت، وكيف تتحقق، وكيف تتمدد على باقي
الأقسام (الرشق، الألعاب، الأرقام...).

---

## 1) المطلوب (بساطة)

> «أضيف 5 مزودين لنفس القسم، والمستخدم قبل ما يختار الدولة يختار السيرفر،
> وكل سيرفر مربوط بمزود لحاله، وأتحكم فيه بالكامل من لوحة الأدمن.»

## 2) البنية المختارة

كل خدمة أرقام `NumberService` يمكن أن تحوي جدول سيرفرات `NumberServer`:

| الحقل | المعنى |
|---|---|
| `number_service_id` | الخدمة (واتساب، تيليجرام...) التي ينتمي لها السيرفر |
| `provider` | المزود المرتبط (5sim / HeroSMS / SMS-Activate / SMSHub) |
| `name_ar` / `emoji` | الاسم والرمز الظاهر للمستخدم |
| `is_active` | تفعيل/تعطيل السيرفر |
| `sort_order` | ترتيب ظهور السيرفرات |

السبب في تصميم السيرفر كجدول مستقل (وليس حقول في الخدمة): لأنه **قابل للتوسّع
بدون تعديل كود** — تضيف سيرفر جديد = صف جديد في قاعدة البيانات، وما تكتب كود.

## 3) ماذا نفّذنا (المرحلة الأولى: قسم الأرقام)

- ✅ جدول `number_servers` + هجرة Alembic جديدة (`f1e2d3c4b5a6`).
- ✅ خدمة `services/number_server_service.py`:
  - إضافة سيرفر
  - تعطيل/تفعيل
  - تعديل الاسم/الإيموجي/المزود
  - حذف
  - إنشاء تلقائي «سيرفر لكل مزود عليه كود» من أزرار الخدمة
- ✅ تدفق المستخدم أصبح:
  ```
  زر الأرقام ← اختر الخدمة
              ← اختر السيرفر (5sim / HeroSMS / SMS-Activate ...)
              ← اختر الدولة
              ← السعر (من المزود المختار فقط)
              ← شراء
  ```
- ✅ الشراء الفردي والجملة مربوطان بـ `strict_provider`:
  - بدون سيرفر → نفس السلوك القديم (أرخص مزود + Failover).
  - مع سيرفر → يشتري من المزود المختار فقط ولا ينتقل لغيره (شفافية السيرفر).
- ✅ لوحة الأدمن: `إدارة خدمات الأرقام` ← أي خدمة ← «⚙️ السيرفرات/المزودين التابعين».

## 4) التوسع على كل الأقسام (الرشق / الألعاب / المتجر) — منفّذ

نفس النمط أصبح جدولاً عمومياً `store_servers`:

| الحقل | المعنى |
|---|---|
| `scope` | `category` / `subcategory` / `global` |
| `scope_id` | رقم القسم (أو 0 لم يعمل على كل الأقسام) |
| `provider_kind` | `api` (متجر/رشق/ألعاب) أو `number` (أرقام) |
| `api_provider_id` | المزود المرتبط إذا كان API |
| `provider_value` | المزود المرتبط إذا كان أرقاماً |
| `margin_percent` | نسبة ربح السيرفر (تُطبق عند الشراء) |
| `name_ar` / `emoji` / `description` | العرض للمستخدم |
| `is_active` / `sort_order` | تفعيل وترتيب |

وسيرفر الأرقام `NumberServer` أصبح يحمل `margin_percent` أيضاً: من لوحة
أدمن الأرقام ← أي خدمة ← «⚙️ السيرفرات/المزودين التابعين» ← أي سيرفر ←
«💰 نسبة الربح». تُطبَّق على الشراء الفردي والجملة وتتفوق على هامش
الخدمة/الدولة الحالي.

### هامش «كل تطبيق/قسم فرعي» (التحكم الدقيق بالأسعار)

من «إدارة الأقسام» يمكن ضبط هامش مستقل على:
- القسم الرئيسي (مثل «الرشق»).
- أي قسم فرعي/تطبيق (مثل «انستقرام»).
- أي خدمة داخل التطبيق (مثل «لايكات» أو «متابعون»).

أولوية الهامش الفعّال عند العرض والشراء:

```
منتج (يدوي) > قسم فرعي/خدمة > تطبيق > قسم رئيسي > سيرفر > السعر المحفوظ
```

- أي منتج سحوب تلقائياً يحمل هامشاً ضمنياً؛ هذا الهامش ليس «يدوياً»،
  لذلك هامش تطبيقه/قسمه يتحكم به ويعيد حساب سعره فوراً.
- إذا ضبط الأدمن هامش المنتج نفسه من شاشة المنتج، يُعتبر يدوياً ولا
  يُلمس عند تغيير هامش القسم.
- هامش السيرفر يُستخدم فقط عندما لا يوجد هامش تطبيق/قسم/منتج مضبوط.

المسار المتصل حالياً:
- المتجر الذكي (`store:section:`) → إن وُجد سيرفر «عام» يُعرض اختيار
  السيرفر أولاً، ثم منتجات مزوده فقط.
- الأقسام الديناميكية (`cat:` → `subcat:`) → إن وُجد سيرفر للقسم الفرعي
  (أو للأب / العام) يُعرض الاختيار قبل المنتجات.
- الشراء: `_execute_purchase` يقرأ `server_id` من الجلسة ويطبّق
  `margin_percent` على سعر التكلفة (يحلّ الهامش القديم) ثم يحسب الإجمالي.
- الأرقام: لا تزال تستخدم `NumberServer` بنظامها الحالي.

## 5) لوحة الأدمن

`/admin` ← «🛍 المتجر والخدمات والرشق» ← «🖥 السيرفرات العامة»:
- عرض كل السيرفرات.
- إضافة سيرفر: اختيار النطاق (قسم رئيسي/فرعي/عام) → الاسم → الإيموجي →
  نوع المزود → المزود → نسبة الربح.
- إدارة: تفعيل/تعطيل، تعديل الاسم/الإيموجي/الوصف/نسبة الربح، حذف.

## 6) كيف تشغّله؟

1. حدّث البوت بالكود الجديد (فيه هجرة قاعدة بيانات).
2. افتح: `/admin` ← «🛍 المتجر والخدمات والرشق» ← «🖥 السيرفرات العامة».
3. أضف سيرفراً واربطه بمزود واضبط نسبة ربحه.
4. إذا ربطته بقسم فرعي يظهر للمستخدم قبل منتجات ذلك القسم؛
   وإذا جعلته «عام» يظهر في المتجر الذكي (ألعاب/رشق/تطبيقات)
   وفي كل قسم لا يحمل سيرفراً خاصاً به.

# سيرفرات قسم الأرقام: أسماء محايدة + النقطة الخضراء

## المشكلة

كانت سيرفرات قسم الأرقام تُعرض للزبون بأسماء المزودين (`5sim`،
`HeroSMS`، `SMS-Activate`، `SMSHub`) — وهذا يكشف مزوّدينا للزبون
ويسمح له بالشراء منهم مباشرة.

## الحل

الزبون يرى **أسماء مرقّمة محايدة فقط**: «سيرفر 1، سيرفر 2، سيرفر 3».

- الترقيم **مستقل داخل كل خدمة**: واتساب لديه سيرفر 1/2/3،
  وتيليجرام لديه سيرفر 1/2/3 — كل خدمة تبدأ من 1.
- الترتيب حسب `sort_order` داخل الخدمة، والترقيم **بلا فجوات**:
  عند حذف سيرفر يُعاد الترقيم تلقائياً فلا يرى الزبون «سيرفر 1»
  ثم «سيرفر 3».
- اسم المزود محفوظ في عمود `provider` — **للأدمن فقط**، ولا يظهر
  للزبون في أي شاشة.

عند إقلاع البوت يعمل `NumberServerService.renumber_all()` تلقائياً،
فيُصلح أي قاعدة بيانات قديمة كانت أسماء سيرفراتها بأسماء المزودين.

## 🟢 النقطة الخضراء (السيرفر الشغّال)

الأدمن يعلّم يدوياً أي سيرفر يعمل فعلياً، فتظهر نقطة خضراء أمامه للزبون:

```
🖥 سيرفر 1
🟢 🖥 سيرفر 2      ← المعلَّم شغّالاً (HeroSMS مثلاً)
🖥 سيرفر 3
```

**الطريق:** `/admin` ← «📱 خدمات الأرقام» ← اختر الخدمة ← «🖥 السيرفرات»
← اختر السيرفر ← «🟢 علّمه شغّال» (نفس الزر يزيل العلامة).

في لوحة الأدمن وحدها يظهر اسم المزود بجانب الاسم المرقّم وعلامة
«🟢شغّال»، ليعرف الأدمن أي سيرفر يقابل أي مزود.

## ملاحظات تقنية

- عمود جديد `number_servers.is_working` (هجرة `d5e6f7a8b9c0`).
- `NumberServerService.set_working(session, id, True, exclusive=True)`
  يعلّم سيرفراً واحداً ويزيل العلامة عن بقية سيرفرات نفس الخدمة.
- لم يعد الأدمن يعدّل اسم/إيموجي السيرفر يدوياً — الاسم مولّد ومحايد،
  وإضافة سيرفر تحتاج اختيار المزود فقط.

# كيف أضيف أكثر من مزود أرقام؟ (كل مزود = سيرفر مستقل)

المطلوب عملياً: «عندي حسابين/ثلاثة عند مزودين مختلفين، وأبغى كل مزود يظهر
للزبون كسيرفر مستقل داخل قسم الأرقام، وكل شي يشتغل مدموج.»

## الخطوة 0 — مفاتيح المزودين (مرة واحدة، في `.env`)

المزودون المدعومون الآن: `5sim` / `HeroSMS` / `SMS-Activate` / `SMSHub`.
كل مزود تريد تشغيله يحتاج مفتاحه في `.env` ثم **إعادة تشغيل البوت**:

```env
FIVESIM_API_KEY=...
HEROSMS_API_KEY=...
SMS_ACTIVATE_API_KEY=...
SMSHUB_API_KEY=...
```

- المزود بلا مفتاح **لا يُهيَّأ إطلاقاً** في `ProviderManager`، فأي سيرفر
  مربوط به سيظهر للزبون بلا أرقام.
- لوحة الأدمن توضح هذا فوراً: «🛍 المتجر والخدمات والرشق» ← «📞 إدارة خدمات
  الأرقام» ← الخدمة ← «⚙️ السيرفرات/المزودين التابعين» يظهر فيها سطر
  «⚠️ مزود بلا مفتاح API: …»، وشاشة «➕ إضافة سيرفر» تعرض أي المزودين
  جاهز بمفتاح وأيها بلا مفتاح، وشاشة السيرفر نفسه تعرض «🔑 مفتاح API
  للمزود: ✅ مضبوط / ⚠️ غير مضبوط».

## الخطوة 1 — كود الدولة وكود الخدمة لدى كل مزود

السيرفر لا يعرض إلا الدول/الخدمات التي لها **كود لدى مزوده**:

- «🌍 إدارة الدول» ← كل دولة تُسأل عن: كود 5sim، كود HeroSMS، كود
  SMS-Activate، كود SMSHub (اكتب `-` لمن لا تريده).
- «📞 إدارة خدمات الأرقام» ← الخدمة (واتساب/تيليجرام…) تُسأل عن نفس
  الأكواد الأربعة لكل مزود.

مثال: واتساب عند 5sim كوده `wa` وعند HeroSMS كوده `whatsapp`، وإندونيسيا
`indonesia` عند 5sim و`id` عند HeroSMS → السيرفران يعرضان إندونيسيا،
وكل واحد بسعر مزوده.

## الخطوة 2 — إنشاء السيرفرات (بلا كود)

«🛍 المتجر والخدمات والرشق» ← «📞 إدارة خدمات الأرقام» ← اختر الخدمة ←
«⚙️ السيرفرات/المزودين التابعين»:

- «🤖 إنشاء سيرفر لكل مزود مضبوط تلقائياً» — ينشئ سيرفراً لكل مزود له كود
  في هذه الخدمة (الأسرع).
- «➕ إضافة سيرفر» — تختار المزود فقط، والاسم يُولَّد محايداً («سيرفر 3»).
- داخل أي سيرفر: تفعيل/تعطيل، تغيير المزود، «💰 نسبة الربح»، «🟢 علّمه
  كسيرفر يعمل الآن»، حذف (مع إعادة ترقيم تلقائية بلا فجوات).

## الخطوة 3 — ماذا يرى الزبون

```
📱 الأرقام ← واتساب
            ← 🖥 سيرفر 1 / 🟢 🖥 سيرفر 2      (بلا أي اسم مزود)
            ← دول هذا السيرفر فقط، مرتبة من الأرخص
            ← السعر ← تأكيد الشراء
```

- الشراء **مقفل على مزود السيرفر**: لا failover لمزود آخر، ولو فشل الشراء
  يُسترجع الرصيد كاملاً.
- «📦 شراء بالجملة» يحمل نفس السيرفر (`strict_provider` + هامش السيرفر).
- هامش السيرفر (إن ضُبط) يتفوق على هامش الخدمة/الدولة.

## ملاحظة: إضافة مزود جديد غير الأربعة

الأربعة أعلاه مبرمجة في `providers/` ومربوطة بـ `ProviderName`. إضافة مزود
خامس (مثل sms-man أو 365sms) تحتاج كوداً، لا لوحة أدمن:

1. `providers/<new>.py` يرث `BaseProvider` (get_price / buy_number /
   check_status / cancel_order / finish_order / get_balance).
2. قيمة جديدة في `ProviderName` + عمود كود للدولة والخدمة
   (`countries.<new>_code`, `number_services.<new>_code`) + هجرة Alembic.
3. مفتاح في `config.py` و`.env.example`، وتسجيله في
   `ProviderManager._init_providers` + `_get_provider_code` +
   `_get_service_code`، واسمه في `PROVIDER_LABELS`.

بعدها يظهر المزود الجديد تلقائياً في شاشة «إضافة سيرفر» وفي الإنشاء
التلقائي، بلا أي تعديل آخر على واجهة الزبون.

## اختبار التغطية

`tests/test_multi_provider_number_servers.py` يشغّل المسار الحقيقي بمزودَين
وهميين: كل مزود يصبح سيرفراً مستقلاً بأسعاره، والشراء يتم من مزود السيرفر
المختار حصراً، وهامش السيرفر يُطبَّق، وإضافة سيرفر ثالث من لوحة الأدمن
تعمل، والتحذير يظهر عند ربط سيرفر بمزود بلا مفتاح.

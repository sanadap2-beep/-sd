# ربط أي مزود أو متجر بدون تعديل الكود

الفكرة في البوت:

```text
زر / قسم → قسم فرعي → منتج → طريقة تنفيذ
```

طريقة تنفيذ المنتج تكون واحدة من:

- `api`: يرسل الطلب تلقائياً إلى مزود مربوط.
- `inventory`: يسلم كود/حساب/بطاقة محفوظة ومشفرة في المخزون.
- `manual`: طلب يدوي يراجعه الأدمن.

## هل يمكن ربط موقع يبيع أي شيء مثل مثلجات؟

نعم إذا كان الموقع يوفر API أو لوحة مزود فيها endpoints. من لوحة الأدمن:

1. افتح `🔌 مزودو المتجر`.
2. اختر `➕ إضافة مزود جديد`.
3. اختر `🛠 Custom JSON`.
4. اختر قالب `🛍 متجر/منتجات REST`.
5. أدخل نوع المزود `🛍 مزود متجر عام` أو النوع المناسب.
6. أدخل رابط API والمفتاح.
7. اختبر الاتصال واحفظ.
8. اسحب المنتجات/الخدمات.
9. حوّل الخدمات المسحوبة إلى منتجات داخل أي قسم أو قسم فرعي.

إذا كان الموقع لا يوفر API وإنما صفحة ويب فقط، لا يوجد ربط تلقائي مضمون بدون
سكرابر/متصفح آلي خاص، وعندها الأفضل إنشاء منتجات `manual` أو `inventory`.

## قالب متجر REST الافتراضي

يتوقع القالب endpoints تقريبية:

```text
GET  /products
POST /orders
GET  /orders/{order_id}
```

ويمكن تعديل JSON لاحقاً إذا كان الموقع يستخدم أسماء مختلفة.

مثال order payload:

```json
{
  "product_id": "{service_id}",
  "customer_note": "{target}",
  "quantity": "{quantity}"
}
```

- `{service_id}` = رقم المنتج/الخدمة عند المزود.
- `{target}` = بيانات العميل التي يدخلها المستخدم: رابط، معرف، عنوان، ملاحظة.
- `{quantity}` = الكمية.

## أمثلة ربط

### رشق
- البروتوكول: `SMM V2`
- المنتج يحتاج رابط وكمية.

### شحن ألعاب
- البروتوكول: `Games JSON` أو `Custom JSON`
- المنتج يحتاج Player ID غالباً.

### متجر عام أو منتجات خارجية
- البروتوكول: `Custom JSON`
- القالب: `متجر/منتجات REST`
- المنتج يستخدم حقل الهدف كملاحظة/عنوان/معرف العميل.

### أكواد وحسابات وبطاقات
- الأفضل: `inventory`
- تخزن بيانات التسليم في المخزون الرقمي المشفر.

### خدمات تحتاج متابعة بشرية
- الأفضل: `manual`
- لا تحتاج API.
